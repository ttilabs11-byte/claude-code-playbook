# Glossary

Copy to the repo root as `GLOSSARY.md`. One line per domain term: the one word the code, specs, UI and tests all use,
what it means, and the words not to use for it. Agents read this before naming things, so a concept keeps one name.
Add a term when a spec introduces one; fix a line when its meaning changes. Keep it alphabetical and short.

| Term | Meaning | Not |
|---|---|---|
| Example term | One sentence: what it is in this product, and where it lives (table, module, screen). | synonyms to avoid |
